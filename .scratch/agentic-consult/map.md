## Decisions so far

1. **执行顺序 = 票号**：01 扩库 → 02 混合检索 → 03 评测集 → 04 ONNX 重排 → 05 闭环 A →
   06 闭环 B → 07 闭环 C → 08 降级容错 →（可选）09 LangChain。
2. **先扩库再评测**：活库 `t_knowledge_chunk = 3` 而 `RETRIEVAL_TOP_K = 5`，
   池子不足时 `recall@5` 恒等于 100%，评测数字没有信息量（→ 票 01 是第一票）。
3. **重排走 ONNX 不走 torch**：`onnxruntime 1.30.0` 与 `tokenizers` 已在 `.venv`；
   `onnx/model.onnx` 1112.5 MB 自带权重、单文件；单对 29.8 ms（→ 票 04）。
4. **闭环反哺走串行预取传值**，不新建 `PatientContextPort`——避免同时踩
   `OrchestrationPorts` 22 个构造点、`gather` 位置索引、回放 FIFO 三处雷（→ 票 07）。
5. **新能力优先放进既有端口的实现层**，让编排层调用序列不变——这样录制/回放、
   `tests/doubles.py`、baseline 都不用动（→ 票 02 的 RRF、票 04 的首选方案 A）。
6. **`regression/divergences.py:19` 的正则只认 `A-*` / `H-*`**：开新族必须同改正则，
   否则新登记的有意偏离被静默忽略、不被回归豁免（→ spec.md 4.6，票 07）。
7. **`server/.tmp` 的 27 个 ACL 拒绝访问目录已清理**，`server/_probe_live.py` 与
   `server/_probe_rerank.py` 两个探针已删除；仓库根递归搜索恢复正常（2026-10-11 开工前置）。
8. **`S-*` = 独立 scope `stack` + `stack_ids()`**（2026-10-11 用户拍板）。族 ↔ scope 一一对应
   （`A`=ai-chain / `H`=http-contract / `S`=stack）；`stack` 不进任何豁免集，
   避免扩大漂移/幻觉分母、让门禁对本次改动失明。**票 02 第一件事**是扩
   `regression/divergences.py` 的正则与访问器。
9. **新增 divergence 条目必须同改两条硬编码等式断言**：
   `test_regression_divergences.py:21`（ai-chain）、`test_acceptance_024.py:155`（http-contract）。
10. **评测集在跑指标之前定稿**，不允许事后回溯调整真值（票 03）。
11. **取消分支的 span 缺口顺手修**：`protocol.py:66` 的 `except Exception` 捕不到
    `CancelledError`，补 `BaseException` 分支写 `cancelled` span（落点票 02「顺带修」）。
12. **本阶段不动简历**（含技能栏 `Docker 基础`）。

### 三份基线的语义差异（**别混为一谈**）

| 版本 | 语义 | 端口来源 | 能证明什么 |
|---|---|---|---|
| `v1` | **fixture 替身语义** | `FixtureGraphPort` / `FixtureRetrievalPort` / `ScriptedLlmPort` | 只证明编排链路的形状；拦截率 / 误拦率是替身自证 |
| `v2` | 同上（用例多带了档案输入） | 同上 | 同上；相对 v1 的真增量只有 `evidence_match_rate` |
| `v3` | **真实调用快照语义**（TICKET-AC-10） | 真实 Neo4j / 活库向量检索 / 真实模型（`record --live`） | 拦截率 / 误拦率是**真实测量**；幻觉率带 AC-10 §3 的上下文缺陷（上下文不含图谱片段） |

`v3` 已于 2026-10-11 录满 **20 条**（AC-10 阶段一 6 条红旗 + 阶段二 14 条正常，
7.65 min / 972 KB）。阶段一单独立项过一条能力边界，值得记着：**红旗用例在安全门就短路**，
实测用替身录一遍帧与它**逐字一致**——所以那 6 条只能证明注入路径打通；
真实 Neo4j / 检索 / 模型三条链路是由阶段二的 14 条正常用例证明的
（gate 先录 1 条并立刻回放，确认 FIFO 回放能吃下活库调用序列）。
`v3` 是**一次真实调用的快照**，不可由同一命令复现；但回放逐字稳定，
`evidence_match_rate` 与 `replay --compare` 不受影响。

**v3 幻觉率的条件标注（读数字前必读）**：该缺陷（判定上下文只由检索端口构建、
不含图谱片段）**已由 TICKET-AC-11 修复**。v3 上重算：`total 400` 不变、
无据 **44 → 33**、`deterministic_ratio` **0.1100 → 0.0825**；
修复前数字保留在 spec §8.3 与票 10 §3。

⚠️ **修复后剩余的 33 条仍不能当"真实幻觉"引用**：其中 **26 条只由数字 token 触发**
（列表编号 / 时长 / 剂量），是指标伪影；只有 7 条含词表项（部分还是提问）。
即**断言抽取口径本身**是第三个缺陷，见下一条待办占位。

**另外（比上面更硬的一条）**：`diagnosis_drift_rate` 在**回放路径上是恒真式**——
`replay.py:94-100` 的 `baseline_candidates` 从同一份基线的 frames 读出，回放喂回的又是
同一批录制数据，两者必然相等，`drifted` 恒为 0。**实测：v1 与 v3 的候选在 12/20 条上
不同，两边仍报 0.0**；它在代码改坏时也报 0。**v1 / v2 / v3 的回放漂移率全是构造性零。**
该指标只在 **record 路径**上有意义。要让 drift 真正可测需要让回放**重新执行**，
那会动摇 AC-B-35「回放零外部依赖」——**另一个范围，不在票 10 里顺手改**。

### AC-10 之后的可引用边界（引用前必读）

> 📌 **唯一权威清单是 [`METRICS.md`](METRICS.md)**；下面这段是它的摘要，冲突时以 METRICS.md 为准。

✅ 可引用：**红旗拦截率 1.0 / 误拦率 0.0**（v3：6 条真实跑真拦截）；
**分母量级**（v1 的 5 → v3 的 400 条被评估断言）；以及**字面层的覆盖率事实**——
「1267 条断言中 400 条（32%）可判定，未评估的 867 条中大量是安全提示句；
33 条被标记无据，其中 24 条由行首列表编号触发」。
**该层的瓶颈是覆盖率（~32%），不是准确率**：它评不到的 68% 里装着就医 / 急诊 /
警惕类提示——这些词一个都不在 `_DETERMINISTIC_TERMS` 里。
❌ **不引用任何 ratio 形态的幻觉率数字**（0.0825 / 0.0664 / 0.0663）——分子被编号伪影污染、
分母随口径变化、横向不可比。对外只报一个数字时用 `literal_marked_ratio`
（33 ÷ 1267 = **0.0260**，分母固定、口径可比），并标注「字面标记率，不是幻觉率」。
一句话：「第一次有了真实分母（400 条被评估断言），但抽取口径仍在校准中，
所以比率暂时不作为幻觉率引用；**更该讲的是覆盖率只有 32% 这条。**」

❌ 不可引用：`diagnosis_drift_rate`（回放恒真式）、`latency` 的 v1→v3 差值
（两种录制产物之差；v3 的 60 s 只能表述为「v3 录制的单次生成耗时 P95 ≈ 60 s」）、
`evidence_match_rate`（同一份快照自我回放的一致性自检）。
