## 3. 幻觉率必须带条件标注（选分票方案的核心）

阶段二产出的幻觉率，必须在**票面 / `spec.md` / `map.md` 三处**同时写上这段标注：

```
本次幻觉率由**确定性字面层**产出，其判定上下文**仅由检索端口构建**
（regression/replay.py:55-62），不含图谱片段——因此依据图谱结论的
疾病名/药品名/检查名会被判为无据。该缺陷未在本票修复，
故本数字**不等于**真实幻觉水平。
```

（修复与重算属 **AC-11**，等本票阶段二落地后再开。）

**这条缺陷的具体表现（可复现的靶子，AC-11 开工时直接用）**：
依据图谱结论说出的疾病名 / 药品名 / 检查名会被判无据。实测例子
（v3 的 `llm-explicit-symptoms` 用例）：

- 真实回答里有一条断言：`知识图谱初步提示：**慢性肾炎（覆盖率约0.50，科室：肾内科，依据症状：高血压）**`；
- 确定性层从这条断言里取到词表命中 `['高血压', '0.50']`；
- 判定上下文（**只由检索端口构建**）里没有「高血压」，于是整条被判**无据**；
- 但「高血压」恰恰是图谱候选（`infer_diseases` 的返回）里的节点名。

更短的一个（`llm-headache-alias`）：断言 `仅说"头疼"还不能判断具体原因，偏头痛、感冒/感染…`
命中词表 `感冒`，检索上下文里没有、图谱候选里有 `{"disease": "感冒"}`——同样被判无据。

全量实测：确定性层共评估 **400** 条断言，其中无据 **44** 条（11%），
而 44 条里有 **10 条**的缺失词出现在图谱结果里——这就是本缺陷的直接代价
（精确重算留给 AC-11，那 10 条是下界，不是全貌）。

**2026-10-11 更新：该缺陷已由 TICKET-AC-11 修复。** 判定上下文改为
「检索分块原文 + 图谱候选数据值（不含任何模板词）**且只取提示词真正注入的前 5 条**」。
v3 上重算：`total 400` 不变，无据 **44 → 33**，`deterministic_ratio` **0.1100 → 0.0825**。
两个对照变体都与正式版**完全一致**：模板词版 `B − A = 0`；全量候选版 `A' − A = 0`
（截断到 5 条不改变数值，但它是**正确性**要求——"模型看到什么就只拿什么判"）。

⚠️ **修复后剩下的 33 条不等于"真实幻觉"，而且 `0.0825` 不该叫"幻觉率"**：

| 分类口径 | 数字 | 含词表项 |
|---|---|---|
| 按「全部 token 全是数字」 | **24** | 9 |
| 按「缺失 token 全是数字」 | 26 | 7 |

口径②（排除行首列表编号）实测：无据 **33 → 14**，即 **19 条无据（58%）是编号伪影**；
按"token 全是数字"计则是 **24/33 = 73%**。且剩下的数字不全是伪影——
`15–20 分钟`、`24 小时尿蛋白定量` 是**真实且应当被证明的临床断言**，与编号需要不同处理。
这是**第三个缺陷**（断言抽取口径），不在 AC-11 范围内，见 **AC-12**。

## 6. 边界与坑

- **网络与外部依赖**：录制需要真实嵌入服务 + 模型 + Neo4j。沙箱内会被拦成
  `OpenAIConnectionError`（实测过）；失败现象是 `error` 帧 503 + `引用=0`，
  不是崩溃——排查时先看帧再怀疑代码。
- **成本**：阶段二要真的花 API 钱（14 条 × 完整回答）。建议先只录 1–2 条确认体积与
  耗时，再决定是否一次录满。
- **端点与后端**：走 `.env` 的 `OPENAI_BASE_URL`；默认后端是 `langchain`（票 09），
  必要时可用 `LLM_BACKEND=http` 对照，两者增量产出逐字相同。
- **别把 v3 说成"真实基线"就完事**：它的**拦截率/误拦率**是真数字，
  但**幻觉率**带 §3 那条缺陷（上下文不含图谱片段）。
- 录制是**串行**的（`record_case_set` 的列表推导），20 条就是这个耗时，别无谓并行。

  **「同一份快照自我回放的一致性自检」**；它真正的用途是在**代码变更后重放旧基线**
  （v2 相对 v1 就是这么用的）。

#### 概念问题 1：v3 的 `drift_rate` 还有意义吗？

**比"v3 没有这个含义"更硬的说法：`drift_rate` 在回放路径上是恒真式
（tautology），不能作为任何稳定性 / 回归证据被引用——三份基线都一样。**

机制：`replay.py:94-100` 里 `candidates` 来自回放（喂回的就是录制数据），
`baseline_candidates` 直接读**同一份基线**的 `frames`，两者必然相等；
`metrics.py:218-222` 于是恒得 `drifted = 0`。这是**测量假象，不是口径问题**。

实测（本票取证脚本 `.tmp/verify_drift_tautology.py`）：

```
v1 与 v3 的图谱候选不同的用例：12/20
  llm-headache-alias:   v1=['感冒', '高血压']        v3=['偏头痛', '感冒', '感冒']
  llm-bellyache-alias:  v1=[]                        v3=['子宫肌瘤', '小儿腹泻', '尿路感染']
v1: candidates == baseline_candidates 恒成立=True → 报告 drift_rate=0.0
v3: candidates == baseline_candidates 恒成立=True → 报告 drift_rate=0.0
```

候选明明在 12/20 条上不同，两边都报 0.0——**它在代码改坏时也会报 0**。

`drift_rate` **只在 record 路径上才有意义**（`test_regression_metrics.py:137`
那条 1/3 是对它的有效单元验证）；回放路径上的值一律不可引用。

**已知局限（另开范围，不在本票顺手改）**：要让 drift 真正可测，回放必须
**重新执行**（例如重新跑图谱查询）而不是喂回录制数据——那会动摇 AC-B-35
「回放零外部依赖」的地基，属**另一个范围**。本票只把它记为已知局限。

**因此 v3 的漂移率没有任何可引用用途**；要监测代码改动，仍然用 v1/v2
（且必须在 **record 路径**上重新录制后对比，而不是回放后比）。
